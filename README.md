# Лабораторная работа №4

**Паттерн:** Фиктивная служба (Service Stub)

**Предметная область:** Магазин электроники с расчетом доставки

**Описание проблемы:**
Функционирование разрабатываемого ПО «Магазин электроники» требует расчета стоимости и сроков доставки заказов. 
В реальной архитектуре данная задача решается путем обращения к внешним логистическим сервисам (API служб доставки: СДЭК, Почта России, Яндекс.Доставка).
Зависимость приложения от сторонней службы создает ряд критических проблем на этапах разработки и тестирования - зависит от ресурсов, которые полностью контролируются кем-то другим,
нередко замедляет процесс разработки, заставляя разработчиков ждать,
пока служба вернется к работе.
Реальные HTTP-запросы к логистическим серверам занимают несколько секунд. Это делает отладку графического интерфейса неудобной, а автотесты – медленными и нестабильными.

**Решение:**
Для устранения описанных проблем в архитектуру приложения внедрим паттерн Фиктивная служба (Service Stub), зависимость вынесена за границу бизнес-логики через шлюз, а подмена реализации осуществляется конфигурационно, без изменения кода ядра системы.
