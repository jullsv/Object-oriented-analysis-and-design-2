***Лабораторная работа №1.***

Паттерн: прототип (Prototype)

Предметная область: автоматизация создания типовых документов в организациях (договоры, счета, акты).

Описание проблемы
Пользователю необходимо создавать десятки документов одного типа (например, 50 счетов в месяц), каждый из которых имеет одинаковую базовую структуру: реквизиты компании, шапка, подвал, стандартные формулировки, стили оформления.

Решение:
В проекте паттерн Prototype используется для создания новых экземпляров документов на основе заранее настроенных шаблонов. Вместо того чтобы каждый раз создавать объект документа «с нуля» и заполнять его одинаковыми данными, система хранит готовые экземпляры-прототипы. При запросе пользователя создаётся копия прототипа, которая затем независимо редактируется. То есть, создаем новый объект через клонирование существующего.

Содержит общие свойства всех документов (DocumentType, DocNumber, Title) и методы Clone(), Save(), Render().

  - Invoice — добавляет поля Amount, ClientName, DueDate

Client – клиент: создает новый объект, обращаясь к прототипу с запросом клонировать себя.
   
Клиент обращается к прототипу, чтобы тот создал свою копию.

Суть применения паттерна:

1. При запуске приложения пользователь вводит реквизиты организации
   (название, ИНН, расчётный счёт, адрес)
2. На основе этих данных создаются 3 прототипа возможных видов документов:
   - invoicePrototype
   - contractPrototype
   - actPrototype
   
   Все прототипы уже содержат общие реквизиты организации.

3. При создании нового документа:
   - Вызывается метод Clone() у соответствующего прототипа
   - Создаётся новый объект с теми же данными
   - Заполняются только уникальные поля присущие документу

4. Документ готов к использованию и сохранению

**Реализация без паттерна**

При запуске проекта без применения паттерна пользователь видит аналогичный интерфейс, однако работа программы отличается. 
Документы создаются традиционным способом - через оператор new с явным заполнением всех полей объекта. Общие данные организации (название, ИНН, расчётный счёт, адрес) хранятся в простых переменных класса MainForm и подставляются в каждый документ вручную при его создании. 

Данная реализация является рабочей, но менее эффективной по сравнению с версией, где применяется паттерн Prototype. Основное преимущество версии с паттерном - сокращение кода и уменьшение риска ошибок за счёт клонирования прототипов с уже заполненными общими данными. А также, я столкнулась с проблемой возможности вносить в код изменения, так как необходимо менять и методы.
