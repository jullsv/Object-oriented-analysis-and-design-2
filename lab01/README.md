***Лабораторная работа №1.***

Паттерн: прототип (Prototype)

Предметная область: автоматизация создания типовых документов в организациях (договоры, счета, акты).

Описание проблемы
Пользователю необходимо создавать десятки документов одного типа (например, 50 счетов в месяц), каждый из которых имеет одинаковую базовую структуру: реквизиты компании, шапка, подвал, стандартные формулировки, стили оформления.

Решение:
В проекте паттерн Prototype используется для создания новых экземпляров документов на основе заранее настроенных шаблонов. Вместо того чтобы каждый раз создавать объект документа «с нуля» и заполнять его одинаковыми данными, система хранит готовые экземпляры-прототипы. При запросе пользователя создаётся копия прототипа, которая затем независимо редактируется. То есть, создаем новый объект через клонирование существующего.

На диаграмме изображены следующие компоненты:

BaseDocument – прототип: объявляет интерфейс для клонирования самого себя. 
Содержит общие свойства всех документов (DocumentType, DocNumber, Title) и методы Clone(), Save(), Render().
   
Invoice, Contract, Act – конкретные прототипы: реализуют операцию клонирования себя. 

Каждый класс создает и возвращает копию самого себя:
  - Contract — добавляет поля Party1, Party2, StartDate, EndDate, Clauses
  - Act — добавляет поля Executor, Customer, ActDate
  - Invoice — добавляет поля Amount, ClientName, DueDate

Client – клиент: создает новый объект, обращаясь к прототипу с запросом клонировать себя.
   
Клиент обращается к прототипу, чтобы тот создал свою копию.
