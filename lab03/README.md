# Лабораторная работа №3

**Паттерн:** посетитель (Visitor)

**Предметная область:** Разработка универсального конвертера файлов (для работы с изображениями и документами).

**Описание проблемы:**
При разработке системы конвертации файлов возникает проблема экспоненциального роста количества классов при использовании наследования.
Если для каждого типа файла (изображение, документ, видео, аудио) и каждой операции (конвертация в JPEG, PNG, PDF, MP4, MP3, валидация, публикация) создавать отдельные подклассы, потребуется огромное количество комбинаций: ImageToJPEG, ImageToPNG, DocumentToPDF, DocumentToJPEG и т.д.
Кроме того, добавление новой операции требует изменения всех существующих классов файлов, что нарушает принцип открытости/закрытости (Open/Closed Principle).
Также возникает проблема дублирования кода — логика конвертации размазана по всем классам, а проверка типов через if/else или switch делает код трудным для поддержки и расширения.

**Решение:**
Применен паттерн Посетитель (Visitor), который позволяет отделить алгоритмы от структуры объектов, над которыми они работают.
 1. Классы файлов (ImageFile, DocumentFile) отвечают только за хранение данных.
 2. Посетители (ConvertToJPEGVisitor, ConvertToPDFVisitor) инкапсулируют логику операций.
 3. Каждый посетитель реализует одну конкретную операцию для всех типов файлов.
 4. Добавление новой операции требует создания одного нового класса без изменения существующих.
 5. Добавление нового типа файла требует создания одного класса файла и добавления метода VisitNewFile() в интерфейс посетителя
 6. Принцип Open/Closed.
 7. Нет проверки типов через if/else — используется полиморфизм.

*Рисунок 1 - диаграмма классов паттерна Visitor*

Основные компоненты:

1. IFile - Базовый интерфейс для всех типов файлов.
   
Содержит метод Accept(visitor), который принимает посетителя.
Определяет общие методы GetName() и GetSize().
Имеет поле path для хранения пути к файлу.

2. ConcreteElements

ImageFile — представляет изображение с полями width, height, format.
DocumentFile — представляет документ с полями pages, wordCount.
Каждый реализует метод Accept(), который вызывает соответствующий метод посетителя (visitor.VisitImageFile() или visitor.VisitDocumentFile()).

3. IFileVisitor (интерфейс посетителя)
   
Объявляет методы VisitImageFile() и VisitDocumentFile() для каждого типа элемента.
Содержит поле outputPath для пути сохранения результата.

4. ConcreteVisitors (конкретные посетители)
   
 - ConvertToJPEGVisitor — конвертирует файлы в JPEG (параметр quality)
 - ConvertToPNGVisitor — конвертирует файлы в PNG (параметр compression)
 - ConvertToPDFVisitor — конвертирует файлы в PDF (параметр pageSize)

5. ObjectStructure
   
Хранит коллекцию файлов.
Предоставляет интерфейс для обхода элементов посетителем.
10. Client (клиент)
Создает структуру файлов.
Применяет посетителей для выполнения операций конвертации.
