# Лабораторная работа №2

**Паттерн:** декоратор (Decorator)

**Предметная область:** создание и кастомизация мемов для социальных сетей.

**Описание проблемы:**
Пользователю необходимо создавать уникальные мемы, комбинируя базовое изображение с различными элементами: текстовыми надписями, фильтрами, рамками, стикерами и водяными знаками.
При использовании наследования для реализации всех возможных комбинаций потребовалось бы создать экспоненциальное количество классов: TextMeme, FilteredMeme, TextBorderMeme, TextFilteredStickerMeme и т.д. Кроме того, пользователь должен иметь возможность динамически добавлять и удалять элементы в процессе редактирования, что невозможно при статическом наследовании.

**Решение:**
В проекте паттерн Decorator используется для динамического добавления обязанностей объекту изображения без изменения его класса. Вместо создания новых подклассов для каждой комбинации эффектов, система оборачивает базовый объект изображения в декораторы, каждый из которых добавляет свою функциональность.

### Общая структура паттерна
 - MemeComponent - Определяет общий интерфейс, для всех объектов, которые можно декорировать.
 - MemeImage - Базовый объект для декорирования
 - MemeDecorator - Базовый класс декоратора, хранит ссылку на декорируемый объект.
 - TextDecorator, FilterDecorator, BorderDecorator, StickerDecorator - Конкретные украшения. (Все четыре класса наследуются от MemeDecorator и добавляют свою функциональность.)

**Методы:**
Сначала вызывается рендеринг базового компонента, затем добавляется текст поверх изображения.
Базовый декоратор просто передаёт вызов внутреннему компоненту, не изменяя поведение.

### Реализация с использованием паттерна Decorator

Архитектура решения включает абстрактный компонент MemeComponent, определяющий общий интерфейс для всех объектов, которые можно декорировать (методы render(), save()).

Базовый класс MemeImage представляет конкретный компонент — исходное изображение мема. Абстрактный декоратор MemeDecorator наследуется от MemeComponent и содержит ссылку на декорируемый объект.

Конкретные декораторы (TextDecorator, FilterDecorator, BorderDecorator, StickerDecorator) расширяют функциональность базового компонента, добавляя соответственно текст, фильтры, рамки и стикеры. 

Каждый декоратор оборачивает предыдущий объект, создавая гибкую цепочку ответственности, где порядок применения декораторов может быть произвольным.

### Реализация без паттерна Decorator

В основе архитектуры лежит монолитный класс Meme, который напрямую хранит все элементы оформления (текст, фильтры, рамки, стикеры) в отдельных векторах внутри себя. 

Каждый тип элемента представлен простой структурой данных (TextElement, FilterElement, BorderElement, StickerElement), а добавление новых функций осуществляется через методы класса (addText(), addFilter(), addBorder(), addSticker()). 

При рендеринге все элементы обрабатываются в жёстко заданном порядке, прописанном в методе render() — сначала применяются фильтры, затем текст, потом рамки и стикеры. 
Такой подход нарушает принцип открытости/закрытости (OCP): для добавления нового типа украшения необходимо модифицировать сам класс Meme, добавляя новые поля и методы. Веб-интерфейс остаётся идентичным проекту с декораторами.

Главное отличие заключается во внутренней архитектуре: вместо гибкой цепочки объектов используется единый класс с фиксированной структурой, что упрощает код на начальном этапе, но затрудняет масштабирование и поддержку при расширении функциональности.
